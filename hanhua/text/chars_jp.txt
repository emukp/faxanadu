; Faxanadu (J) font code table  --  CODE<TAB>character
;
; Built by rendering the glyphs of bank 13 ($0000-$1F3F) and reading them,
; and cross-checked against the English of the same message: the two scripts are
; the same game and line up as **J #N = U #(N+1)**, so every kanji below can be
; read in a sentence whose meaning is known.
;
; GLYPH FORMAT (corrected in this revision - the earlier note in
; docs/Faxanadu-UvsJ.md 5.2 called it "8x16, 2bpp, plane0[16]+plane1[16]",
; which is wrong): a glyph is **16x16, 1bpp, 32 bytes**, stored as
;     bytes  0..15 = the LEFT  8 columns, one byte per row (bit7 = leftmost)
;     bytes 16..31 = the RIGHT 8 columns, same rows
; Rendering the two halves as two bitplanes of an 8x16 cell (the old reading)
; turns every wide kanji into a plausible-looking but wrong shape - it is what
; made the first pass at this table unreliable.
;
; Code layout:
;   $00-$51  hiragana, dense 五十音 with the small kana inline
;            (あ ぃ い ぅ う ぇ え ぉ お / た だ ち ぢ っ つ づ て で と ど)
;   $52-$A1  katakana, same layout, then ヮ ワ ヲ ン
;   $A2-$F9  kanji and symbols; the font only carries the glyphs this script
;            needs, e.g. the digits are 0 1 2 3 5 8 only (no 4/6/7/9 anywhere)
;   $FD space  $FE newline  $FC pause  $FB player title  $FF terminator
;
; Two entries are deliberately glossed rather than literal:
;   $A8  the glyph is 一, but every one of its 79 uses is a katakana long vowel,
;        so it is entered as ー (the mark the text actually reads as).
;   $A0  is not used by any message; it is entered as ヲ (the only katakana left
;        in the わ row) but was not confirmed against a running text.
; Codes with no line here are unresolved and print as <XX> in messages_jp.txt,
; so a guess can never be mistaken for a reading.
